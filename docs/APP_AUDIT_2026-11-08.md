view methods.

## 3. Fixed in this pass

| Area | Problem | Fix |
|---|---|---|
| Sign-in | Login was case-sensitive on the email (`Ali@x.com` failed) | Emails stored and matched case-insensitively (API and Django admin) |
| Sign-in | A lockout after 5 failures said "Incorrect email or password" for 30 minutes | 429 "Too many failed sign-in attempts" |
| Sign-in | Changing letter case bypassed the lockout | Lockout keyed on the lowercased email |
| Sign-in | Login attempts recorded the proxy's IP | Client IP recorded |
| Security | Production could start with the public default secret key (forgeable login tokens) | Production refuses to start; system check E008/E009 |
| Jobs | Two scheduled tasks (monthly hard delete, key-rotation check) were never registered | Registered |
| Storage | S3 settings were ignored on Django 5.1 | `STORAGES`; S3 opt-in with `USE_S3_STORAGE` |
| Billing config | Checkout is 503 without the 100/200-prompt Polar product ids, which were undocumented | Documented; deploy checks them |
| UI | Enterprise SSO links shown while the backend has the feature off | Opt-in with `VITE_ORG_FEATURES_ENABLED=true` |
| UI | Brand-security findings showed only the first 25 | All pages read |
| UI build | Lockfile ignored; several `VITE_*` variables never passed | `npm ci`; all build args passed |
| Legal | Terms existed but nobody accepted them; text contradicted the product | Versioned acceptance on first sign-in; Terms rewritten to match the product |
| AWS prep | Load balancer probes would get 400 (host check) | `/healthz` liveness |
